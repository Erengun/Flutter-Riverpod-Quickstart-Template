# Networking

**Networking.** Core owns one shared `Dio` and the error model (`packages/core/lib/src/network/`); Features call the backend through retrofit clients.
- `dioProvider` (keep-alive) is `createDio(config.apiBaseUrl, ...)` and is never changed after it is built: no base-URL, key or token setters. A client for another host builds its own Dio with `createDio(otherHost, reporter: ..., ...)`. Defaults: timeouts connect 10 s / send 30 s / receive 30 s (override per request through `Options`), `x-api-key` from `AppConfig.apiKey`, no global `Content-Type`.
- Interceptor order: app extras (`dioInterceptorsProvider`; its default is Core's auth interceptor alone, so an app that overrides it to add its own keeps `ref.watch(authInterceptorProvider)` in the list; extras run before retry) → breadcrumb (one per request: method, normalized path, status, duration) → retry (`dio_smart_retry`, `dioRetries` = 3 retries, only GET/HEAD/PUT/DELETE/OPTIONS, only on connection errors, connect timeouts, 408, 429 and 5xx) → logging (dev and staging only, `Logger('network')` at `FINE`, `Authorization` and `x-api-key` redacted). No cache and no connectivity check in Core; a Feature that needs caching adds it to its own Dio.
- A Feature's client is a `@RestApi()` class in its `data/` with the endpoint paths as annotations (e.g. `features/authentication/data/auth_api.dart`), built with `ref.watch(dioProvider)` and `errorLogger: apiParseErrorLogger` (so decode failures keep their request). An abstract repository sits above it, and its implementation wraps every call in Core's `ApiCall` from `apiCallProvider`: `apiCall(() => api.login(body))` for methods returning the model, `apiCall.unwrap(() => api.x())` for methods returning `BaseResponse<T>`. Rerun build_runner after changing a client.
- `BaseResponse<T>` (`base_response.dart`) is Core's default envelope; edit its fields and the unwrap rule next to them to fit your backend. 2xx with `success != true` throws `business` with `errorMessage ?? message`; a 4xx/5xx body's `errorMessage ?? message` is recovered too.
- Every failure becomes a sealed `ApiException`: `ApiConnectionException`, `ApiTimeoutException`, `ApiCancelledException`, `ApiUnauthorizedException` (401), `ApiForbiddenException` (403), `ApiNotFoundException` (404), `ApiServerException` (other 4xx/5xx), `ApiBusinessException`, `ApiDecodeException`, `ApiUnknownException`. Never check `statusCode` yourself; Dio throws on non-2xx.
- Reporting happens only in `ApiCall`: `server`, `notFound`, `decode` and `unknown` are reported once per launch per `<method> <normalized path> <status>` (numeric/UUID segments become `:id`; that string is the group key; tags `http.method` / `http.path` / `http.status`, extra `errorMessage` and the `requestIdHeaderProvider` header, default `X-Request-Id`); repeats and every other kind become breadcrumbs. A failure with no request (thrown before or outside Dio) is deduplicated per kind and cause type and sent without a group key, so the tracker groups it by stack trace. Don't report an `ApiException` again.
- Showing errors: let the `ApiException` reach the UI as an `AsyncError` and call `ref.listenApiErrors(provider, context)` in `build` for a floating snackbar (skips `unauthorized`, which the auth Feature redirects, and `cancelled`; the login screen shows its own 401s, since the login call skips auth and a 401 there means wrong credentials). For a screen whose main data failed, use `ApiErrorView(error:, onRetry:)` in the `error` branch. Messages come from `ApiException.localizedMessage` / `apiErrorMessage` (the backend's message, else Core's default per kind). There is no global error observer.
- Tests: swap `dio.httpClientAdapter` for a fake adapter (see `packages/core/test/support/fake_http_adapter.dart`), pass `retryDelays: const <Duration>[]` to `createDio` to skip the waits, or override the repository provider.
- Network permission is the app's, not a Module's: the main `android/app/src/main/AndroidManifest.xml` declares `INTERNET` (release builds get nothing from the debug/profile manifests) and both `macos/Runner/*.entitlements` have `com.apple.security.network.client`. Keep them when removing Modules.
- The auth interceptor adds `Authorization: Bearer <Session.accessToken>` to every request while signed in, reading the token per request (the Dio is never rebuilt). It never replaces an `Authorization` header the request already has; one that already carries `Bearer <current token>` (a permission loader's) is still refreshed and replayed on a 401. Requests that must go without a token (login, register, refresh) carry `@Extra(<String, Object>{skipAuthKey: true})` on the retrofit method.
- The default backend is reqres.in (test credentials in README); it doesn't wrap responses, so the demo auth client returns the models directly.
